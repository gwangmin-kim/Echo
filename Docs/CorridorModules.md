# 복도 모듈 사용법

## 시작

- 생성 메뉴: **GameObject > Echo > Corridors > Straight / End Cap / Corner / Three Way**.
- 프리셋: `Assets/Prefabs/LevelDesign/Corridors/`의 네 프리팹.
- 샘플: `Assets/Scenes/CorridorModules.unity`. 네 프리셋을 나란히 배치한 구조 확인용 씬이며 플레이어와 조명은 포함하지 않는다.
- 메뉴로 만든 모듈은 바로 수정할 수 있다. 프리팹 인스턴스 하나만 수정하려면 루트 Inspector에서 **Unpack Module for Independent Editing**을 먼저 누른다. 모든 인스턴스에 공통 변경을 적용하려면 원본을 Prefab Mode에서 편집한다.
- 수치를 바꾸고 **Rebuild Geometry**를 누른 뒤 씬 또는 프리팹을 저장한다. 입력값이 잘못되면 이유를 표시하고 생성을 차단한다. 기존 형상은 유지된다.

## 치수와 좌표

내부 폭·높이는 실제 통행 공간의 치수(m)이다. 벽 두께와 바닥/천장 두께는 `Wall / Slab Thickness`를 공유한다. Transform과 부모 Scale은 `(1, 1, 1)`로 두고 치수를 수정한다.

| 종류 | 길이와 피벗 |
|---|---|
| Straight | 루트는 입구 바닥 중앙. 바닥 Y=0, 입구 Z=0, 출구 Z=Length. +Z 방향으로 늘어난다. |
| End Cap | 루트는 막는 면의 바닥 중앙. 벽은 Z=0에서 +Z 방향으로 두께만큼 생성된다. 폭은 양쪽 벽 두께까지 포함한다. |
| Corner | 루트는 두 통로 중심선의 교점, 바닥 Y=0. 두 출입구를 가진다. |
| Three Way | 루트는 세 통로 중심선의 교점, 바닥 Y=0. 출입구는 정확히 세 개다. |

코너와 삼거리의 `Arm Beyond Joint`는 접합부 바깥에 확보하는 직선 구간 길이다. 중심에서 출입구까지의 거리는 폭·벽 두께·최소 각도에 따른 접합 여유 거리와 이 길이를 합해서 계산한다. 폭/각도를 바꾸면 출입구 위치도 변하므로 인접 모듈을 다시 정렬해야 한다.

모듈 안의 모든 출입구는 같은 폭과 높이를 사용한다. `Include Ceiling`으로 천장 생성을 선택한다. 기본 재질은 기존 `SoundReactiveSurface`이며 각 메시에는 `MeshCollider`와 `SoundReactiveSurface`가 있다. 음파가 없을 때 어둡게 보이는 것은 해당 재질의 기존 표현이다.

## 각도: 최소 60°

위에서 바라보는 로컬 좌표를 기준으로 +Z=0°, +X=90°, -Z=180°, -X=270°이다.

- **Port 0**은 항상 -Z(180°)를 향한다.
- 코너는 **Port 1 Yaw**를 조절한다.
- 삼거리는 **Port 1 Yaw / Port 2 Yaw**를 독립적으로 조절한다.
- 제약에 사용하는 각도는 중심에서 두 출입구로 나가는 방향 사이의 **작은 각도(0~180°)**다. 플레이어의 진행 방향 회전량과 구분한다.
- 60°는 허용한다. 그보다 작은 각도는 거부한다. 삼거리는 세 쌍을 모두 검사한다.
- 음수나 360° 이상 값도 같은 방향으로 정규화한다. NaN/Infinity는 거부한다.

| 예시 | Port 1 | Port 2 | 결과 |
|---|---:|---:|---|
| 직각 코너 | 90° | — | 두 출입구 각도 90° |
| 최소 각도 코너 | 120° | — | 두 출입구 각도 60° |
| 반대쪽 최소 각도 코너 | 240° | — | 두 출입구 각도 60° |
| 직선 형태 코너 | 0° | — | 두 출입구 각도 180°, 허용 |
| T자 삼거리 | 90° | 270° | 각 쌍 90°/90°/180° |
| 대칭 Y자 삼거리 | 60° | 300° | 각 쌍 120° |
| 최소 각도 삼거리 | 120° | 240° | 각 쌍 60°/60°/120° |
| 금지 예시 | 0° | 359° | 출입구 1·2 사이가 1° |

전체 방향은 루트 Transform의 Y 회전으로 조절한다.

## 연결

1. 두 모듈의 형상을 먼저 갱신한다.
2. 이동할 모듈의 `Generated/Ports/Port N`을 선택한다.
3. `Destination Port`에 상대 출입구를 지정한다.
4. **Move This Module to Destination**을 누른다.

선택한 모듈 전체를 이동·회전하여 두 출입구의 바닥 중앙을 일치시키고 방향을 반대로 맞춘다. 폭·높이가 다르거나 같은 모듈의 출입구를 지정하면 거부한다. 연결된 모듈의 자동 이동은 없으며 재정렬은 명시적으로 실행한다. 저장과 Undo를 지원한다.

## 재생성과 수동 편집

- `Generated`: 도구가 관리하는 ProBuilder 메시와 연결 지점. 재생성 시 교체된다. 이 아래에 소품을 배치하거나 생성 메시를 직접 수정하면 다음 재생성에서 사라진다.
- `Details`: 가시·장식·트리거 등 수동 배치용. 재생성해도 보존된다. 구조의 치수 변경에 따라 소품 위치까지 자동 보정하지는 않는다.
- 특수한 형태를 직접 편집하려면 **Keep Geometry and Remove Generator**로 모듈 컴포넌트를 제거한다. ProBuilder 형상과 연결 지점 오브젝트는 남는다. 파라미터 재생성과 모듈 연결 버튼은 더 이상 사용할 수 없다. Undo로 되돌릴 수 있다.
- 이 도구는 반복 사용하는 에디터 제작 도구이며, Play Mode에서 형상을 생성하거나 갱신하지 않는다.

## 검증

Unity 6000.3.23f1 / ProBuilder 6.1.2의 연결된 Editor에서 확인했다.

- 124개 사례: 종류별 생성·치수 수정·소품 보존, 60° 경계와 잘못된 각도 차단, 여러 비대칭 삼거리 조합, 회전된 모듈 연결.
- 13,652개 삼각형의 유효 면적 검사, 4,558회 바닥·벽·출입구 Raycast 검사.
- 프리팹 저장 후 샘플 씬 재로딩 시 메시와 충돌체 복원, 재생성 Undo/Redo.
- Play Mode에서 네 모듈의 메시 10개와 충돌체 로드.
- 임시 재질과 천장 숨김으로 직선·끝막음·60° 코너·삼거리 렌더 확인.

기하·충돌 회귀 검사는 프로젝트 루트에서 다음과 같이 다시 실행한다. 실행 중인 Editor가 필요하며 Play Mode 밖에서 사용한다. 임시 additive 씬은 검사가 끝나면 닫힌다.

```sh
unity command eval_file Tests/CorridorModules.eval.cs --format json
```

플레이어로 직접 통과하는 체감, 음파 가시성, 완성된 맵의 동선은 별도 플레이 검증 대상이다.

검증 중 Console에 URP `BloomEditor.OnEnable` / `TonemappingEditor.OnEnable`의 `SerializedObjectNotCreatableException`이 각 1건 기록됐다. 복도 모듈 스택의 오류는 아니며, 해당 URP Inspector 예외의 원인은 이번 범위에서 확정하지 않았다. 따라서 Console 전체가 오류 없이 통과했다고 간주하지 않는다.
