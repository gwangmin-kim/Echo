# Echo — 음파 시스템 설계

> 문서 상태: 1차 프로토타입 설계안  
> 최종 갱신: 2026-09-01  
> 상위 문서: [GDD.md](./GDD.md)  
> 목적: Echo의 핵심 게임플레이인 음파의 논리적 전파, 표면 시각화, 오디오 표현, AI 감지를 일관된 규칙으로 구현하기 위한 기준을 정의한다.

---

## 1. 설계 목표

Echo의 기본 화면은 완전한 어둠에 가깝다. 플레이어는 발걸음, 박수, 투척물 충돌, 적과 환경이 만든 소리를 통해 공간과 위험을 파악한다.

음파 시스템은 다음 경험을 만들어야 한다.

- 소리를 내면 음원의 발생 지점을 중심으로 구형 파면이 퍼진다.
- 음파 자체가 보이는 것이 아니라 파면이 표면과 만나는 부분만 시각화된다.
- 표면의 형상, 종류, 위험성을 짧은 시간 동안 판독할 수 있다.
- 큰 소리는 더 많은 정보를 제공하는 동시에 적에게 더 강한 단서를 준다.
- 적과 소리 반응 장치는 플레이어와 동일한 음파 사건을 감지한다.
- 벽 너머 또는 먼 거리의 소리는 위치를 암시하되 정확한 공간 정보를 항상 제공하지는 않는다.

아름다운 효과보다 판독성, 일관성, 게임플레이상의 공정성을 우선한다.

---

## 2. 핵심 설계 원칙

### 2.1 하나의 음파 사건

시각 효과용 음파와 AI 감지용 소리를 별도로 발생시키지 않는다. 모든 결과는 하나의 `SoundWave` 사건에서 파생한다.

```text
발걸음 / 박수 / 돌 충돌 / 적 행동 / 환경 장치
                        │
                        ▼
                 SoundWaveSystem.Emit
                        │
              하나의 SoundWave 생성
              ┌─────────┼─────────┐
              ▼         ▼         ▼
          논리적 전파  표면 시각화  실제 오디오
          AI/장치 감지 구면 교차 띠 AudioSource/필터
```

이 구조를 통해 음원의 위치, 발생 시각, 범위, 도착 시각이 모든 시스템에서 일치하도록 한다.

### 2.2 객관적 전파와 지각 표현의 분리

음파 데이터는 다음 세 층으로 해석한다.

```text
SoundWave
├─ Propagation: 위치, 시작 시각, 현재 반지름, 최대 범위
├─ Perception: 플레이어에게 보이고 들리는 방식
└─ Detection: AI와 장치가 감지하는 강도와 정보
```

- `Propagation`은 음파의 객관적인 위치와 도착 시각을 결정한다.
- `Perception`은 거리, 표면, 차폐 등에 따라 밝기, 경계, 잔상, 음색을 조절한다.
- `Detection`은 AI 또는 장치가 해당 음파에 반응할지를 결정한다.

차폐나 시각적 흐림을 추가하더라도 구면 전파 자체는 변경하지 않는다.

### 2.3 시각과 게임 로직의 독립성

- 렌더링 슬롯이 부족해 음파가 보이지 않더라도 논리적 감지는 유지한다.
- 화면 밖에 있는 음파도 필요한 경우 AI와 장치에 도달한다.
- 그래픽 품질 설정이 음파의 범위나 AI 반응 결과를 바꾸어서는 안 된다.
- 실제 오디오 클립의 길이, 지연, 볼륨이 논리적 도착 판정을 결정하지 않는다.

## 3. 확정 사항

현재 설계에서 다음 항목을 확정한다.

- 음파는 발생점을 중심으로 3차원 구형으로 확산한다.
- 전파 속도는 모든 음파가 공유하는 전역 고정값이다.
- 현재 반지름은 경과 시간과 전역 전파 속도로 계산한다.
- 음파별로 최대 범위, 시각적 두께, 잔상 시간, 밝기, AI 감지 강도를 설정할 수 있다.
- 음파 자체를 구체 메시나 파티클로 직접 렌더링하지 않는다.
- 파면이 실제 메시 표면과 만나는 부분만 시각화한다.
- 음파의 색상과 패턴은 기본적으로 표면이 결정한다.
- 기본 표면 반응색은 흰색이며, 물과 특수 영역은 고유한 색과 패턴을 가진다.
- AI와 소리 반응 장치는 파면이 자신의 위치에 도착한 시점에 반응한다.
- 1차 프로토타입에서는 물리적 반사, 회절, 다중 경로를 구현하지 않는다.
- 1차 프로토타입에서는 별도의 벽 차폐 없이 순수한 구면 전파를 먼저 검증한다.

상위 GDD에는 음원의 종류와 세기에 따라 전파 속도가 달라질 수 있다고 기술되어 있으나, 본 설계에서는 최신 합의에 따라 전역 고정 속도를 사용한다.

## 4. 전파 모델

### 4.1 기본 계산

음파의 현재 반지름은 다음과 같이 계산한다.

```text
currentRadius = (currentTime - startTime) × globalPropagationSpeed
```

표면 또는 Listener까지의 도착 시각은 다음과 같다.

```text
arrivalTime = startTime + distance(origin, targetPosition) / globalPropagationSpeed
```

현재 반지름을 매 프레임 누적해서 저장하기보다 시작 시각으로부터 계산한다. 프레임 드롭, 일시정지, 시간 간격 변화가 있어도 전파 위치가 누적 오차로 어긋나지 않도록 하기 위함이다.

### 4.2 수명

논리 음파는 현재 반지름이 최대 범위를 넘어가고 필요한 Listener 전달이 끝나면 제거한다.

시각 음파는 마지막 표면 잔상이 사라질 수 있도록 다음 시점까지 유지한다.

```text
visualLifetime = maxRadius / globalPropagationSpeed + traceDuration
```

### 4.3 전파 속도

전파 속도는 현실의 음속을 그대로 재현하지 않는다. 작은 실내에서 실제 음속을 사용하면 파면의 이동이 사실상 즉시 끝나 공간 판독과 긴장 형성에 적합하지 않기 때문이다.

전파 속도는 게임 세계의 표현 규칙이며, 초기 테스트 값으로 `20~30 m/s` 범위를 권장한다. 최종값은 공간 규모와 발걸음 간격을 기준으로 플레이테스트하여 정한다.

## 5. 데이터 모델

아래 이름과 필드는 구현 시 조정할 수 있으며, 책임의 분리를 설계 기준으로 삼는다.

### 5.1 전역 설정

`SoundWaveSettings`는 ScriptableObject로 관리한다.

```csharp
public sealed class SoundWaveSettings : ScriptableObject
{
    public float PropagationSpeed;
    public int MaxVisibleWaves;
    public int MaxLogicalWaves;
}
```

초기 권장 한도는 다음과 같다.

- 동시 시각 음파: 16개
- 동시 논리 음파: 64개

두 한도는 성능 측정 후 조정한다. 논리 한도와 시각 한도는 반드시 분리한다.

### 5.2 음파 프로필

`SoundWaveProfile`은 발걸음, 조용한 발걸음, 박수, 돌 충돌, 적 발소리 등 음원 종류별 프리셋이다.

```csharp
public sealed class SoundWaveProfile : ScriptableObject
{
    public float MaxRadius;
    public float VisualThickness;
    public float TraceDuration;
    public float VisualIntensity;
    public float HearingIntensity;

    public AnimationCurve VisualFalloff;
    public AnimationCurve HearingFalloff;

    public AudioClip AudioClip;
    public float AudioVolume;
    public float AudioPitch;
    public float AudioMaxDistance;
}
```

`VisualIntensity`와 `HearingIntensity`는 분리한다. 시각적으로 잘 보이지만 AI 노출은 작은 소리, 또는 그 반대의 소리를 향후 설계할 수 있기 때문이다.

### 5.3 런타임 음파

```csharp
public readonly struct SoundWave
{
    public int Id;
    public Vector3 Origin;
    public double StartTime;
    public SoundWaveProfile Profile;
    public GameObject Source;
}
```

필요한 경우 발생 시점의 표면 수정값, 무작위 시드, 지각 기반 차폐도를 런타임 데이터에 추가할 수 있다.

### 5.4 범용 음파 범위

1차 구현에서는 음파를 종류별로 분류하지 않는다. 모든 음원은 동일한
`SoundWaveSystem.Emit` 진입점을 사용하고, 필요한 차이는 프로파일의 범위,
강도, 오디오 데이터로 표현한다.

음원 객체 참조(`Source`)는 디버깅과 후속 게임플레이 로직을 위해 유지한다.

Listener는 관심 있는 카테고리만 감지하거나 카테고리별로 다른 행동을 선택할 수 있다.

## 6. 표면 시각화

### 6.1 기본 원리

각 표면 셰이더는 픽셀의 월드 좌표와 활성 음파를 비교한다.

```text
surfaceDistance = distance(pixelWorldPosition, waveOrigin)
waveDistance    = elapsedTime × globalPropagationSpeed
distanceToFront = abs(surfaceDistance - waveDistance)
```

`distanceToFront`가 음파의 시각적 두께 안에 있는 픽셀만 밝힌다. 따라서 빈 공간에는 아무것도 그려지지 않고 구면 파면과 바닥, 벽, 천장, 오브젝트 표면의 교차 영역만 나타난다.

### 6.2 잔상

표면 도착 후 경과 시간은 다음과 같이 계산한다.

```text
timeSinceArrival =
    currentTime - startTime
    - surfaceDistance / globalPropagationSpeed
```

이 값이 `0~traceDuration` 범위에 있을 때 파면 뒤쪽에 감쇠된 흔적을 남긴다.

기본 표현은 다음 세 층을 권장한다.

1. 얇고 밝은 전면 파면
2. 파면 뒤쪽의 넓고 약한 글로우
3. 짧게 유지되는 표면 잔상

URP Bloom은 발광 가장자리를 보강하는 용도로 사용하되, Bloom 자체에 핵심 판독성을 의존하지 않는다.

### 6.3 기본 검은색

반응형 머티리얼은 평상시 검은색을 출력하고 음파 반응만 Emission으로 표시한다.

추후 제한적인 Point Light 또는 Spot Light가 도입될 경우 다음을 구분한다.

- 완전한 음파 전용 표면: Unlit 기반 검은색 + 음파 Emission
- 특수 광원에 반응해야 하는 표면: Lit 기반 검은색 + 음파 Emission

### 6.4 음파 중첩

초기에는 여러 음파의 밝기를 단순 합산하지 않고 가장 강한 반응을 선택하는 `max` 방식을 사용한다. 연속된 발걸음으로 화면이 하얗게 포화되는 것을 막기 위함이다.

음파 교차점을 강조하는 표현은 핵심 판독성이 검증된 이후 별도 실험으로 둔다.

## 7. 표면 반응

### 7.1 표면 프로필

`SoundReactiveSurface`가 `SoundSurfaceProfile`을 참조하고 렌더러에는 `MaterialPropertyBlock`으로 값을 전달한다.

표면 프로필은 다음을 포함할 수 있다.

- 기본 발광색
- 밝기 배율
- 패턴 종류와 크기
- 파면 경계의 형태
- 잔상 시간 배율
- 시각적 감쇠 배율
- 월드 공간 왜곡 강도

### 7.2 초기 표면 표현

| 표면 | 색상 | 경계 및 패턴 | 잔상 |
|---|---|---|---|
| 일반 | 흰색 | 부드러운 단일 띠 | 기준값 |
| 물 | 파란색 | 넓고 부드러운 왜곡 | 길게 유지 |
| 위험 | 적색 또는 주황색 | 날카롭고 불규칙하게 끊김 | 짧고 강함 |
| 트리거 | 노란색 계열 | 규칙적인 고리 또는 격자 | 규칙적으로 감쇠 |
| 흡음 | 탁한 회색 | 진입하면서 빠르게 끊김 | 매우 짧음 |

색상만으로 종류를 구분하지 않는다. 색각 접근성을 위해 경계 모양, 패턴 주파수, 움직임, 잔상 속도를 함께 다르게 한다.

### 7.3 표면 반응과 발생 효과의 분리

표면이 시각적 색과 패턴을 결정하는 것과, 해당 표면 위에서 발생한 소리가 더 크거나 작아지는 것은 별개의 책임이다.

예를 들어 물 위에서 발걸음이 발생하면:

```text
발걸음 발생
→ 발밑 SurfaceType 확인
→ FootstepProfile에 물의 발생 수정값 적용
→ 최종 SoundWave 생성
→ 물 표면은 자신의 파란색 시각 반응 출력
```

물 표면 셰이더가 음파의 논리적 범위나 AI 감지 강도를 직접 변경해서는 안 된다.

## 8. 거리 기반 표현

별도 차폐가 없는 1차 프로토타입에서도 거리 자체로 정보의 정밀도를 조절할 수 있다.

### 8.1 밝기 감쇠

```text
normalizedDistance = surfaceDistance / maxRadius
intensity = visualFalloff(normalizedDistance)
```

가까운 공간은 명확하게 보여주고 최대 범위에 가까워질수록 빠르게 흐려지는 곡선을 권장한다.

### 8.2 경계 폭

멀리 이동한 파면일수록 넓고 흐릿하게 만들 수 있다.

```text
effectiveThickness =
    baseThickness × thicknessCurve(normalizedDistance)
```

띠가 넓어져 전체 밝기가 더 강해지지 않도록 밝기는 반대로 줄인다.

### 8.3 월드 공간 왜곡

완벽한 수학적 원형을 완화하거나 표면별 특성을 나타내기 위해 거리 판정에 작은 월드 공간 노이즈를 더할 수 있다.

```text
distortedDistance =
    distance(origin, worldPosition)
    + worldNoise(worldPosition, waveSeed) × distortion
```

노이즈는 화면 좌표가 아니라 월드 좌표를 사용한다. 카메라가 움직일 때 패턴이 화면에 붙어 흐르는 현상을 방지하기 위함이다.

노이즈 진폭은 파면 두께보다 충분히 작게 유지하여 핵심 윤곽이 끊어지지 않도록 한다.

## 9. 논리적 감지

### 9.1 Listener 계약

AI와 소리 반응 장치는 공통 Listener 계약을 사용한다.

```csharp
public interface ISoundWaveListener
{
    void OnSoundWaveArrived(in SoundWaveHit hit);
}
```

```csharp
public readonly struct SoundWaveHit
{
    public SoundWave Wave;
    public float TravelDistance;
    public float PerceivedIntensity;
    public double ArrivalTime;
}
```

Listener에는 음원 위치와 음파 정보만 전달한다. 적이 플레이어 객체를 직접 참조하지 않아도 돌, 환경 장치, 다른 적의 소리에 동일하게 반응할 수 있어야 한다.

### 9.2 도착 판정

기본 도착 조건은 다음과 같다.

```text
previousRadius < distance(origin, listener)
currentRadius  >= distance(origin, listener)
```

각 Listener는 하나의 음파 ID에 대해 정확히 한 번만 도착 이벤트를 받아야 한다.

### 9.3 감지 강도

```text
perceivedIntensity =
    wave.HearingIntensity
    × hearingFalloff(normalizedDistance)
    × listenerSensitivity
    × optionalObstructionAttenuation
```

`PerceivedIntensity`가 Listener의 최소 임계값 이상일 때 반응한다.

적은 최소한 다음 정보를 사용할 수 있다.

- 마지막으로 감지한 음원 위치
- 감지된 강도
- 음파 카테고리
- 발생 시각과 도착 시각

여러 음파가 도착할 경우 단순히 가장 최근 음파만 따르기보다 강도, 위협도, 신선도를 조합하여 조사 대상을 선택할 수 있다. 구체적인 AI 상태 머신은 별도 문서에서 정의한다.

### 9.4 성능 전략

초기 프로토타입에서는 활성 음파와 Listener 목록의 단순 순회로 시작한다. 적이 한 종류이고 활성 객체 수가 작기 때문에 규칙 검증이 최적화보다 우선한다.

프로파일링 결과가 필요할 때 다음 순서로 확장한다.

1. Listener Layer와 범위 기반 후보 축소
2. 주기 분산 또는 도착 시각 예약
3. 공간 그리드 기반 Listener 조회

매 프레임 팽창하는 SphereCollider를 음파마다 생성하는 방식은 기본 구조로 사용하지 않는다. 동시 음파가 많아질 때 물리 비용, 중복 이벤트, 수명 관리가 복잡해지기 때문이다.

## 10. 기존 플레이어 시스템과의 연결

현재 `FootstepEventEmitter`는 발 위치에서 `FootstepOccurred(Vector3)` 이벤트를 발생시킨다.

권장 연결 구조는 다음과 같다.

```text
FootstepEventEmitter
    → PlayerSoundEmitter
        → 발밑 표면 판정
        → 이동 상태별 SoundWaveProfile 선택
        → 표면 발생 수정값 적용
        → SoundWaveSystem.Emit
        → 실제 발소리 재생
```

`FootstepEventEmitter`는 발걸음이 언제, 어디에서 발생했는지만 책임진다. 셰이더, AI, 표면 규칙을 직접 호출하지 않는다.

박수, 돌 충돌, 적 행동도 각자의 Emitter가 동일한 `SoundWaveSystem.Emit` 진입점을 사용한다.

## 11. 차폐와 원거리 지각 확장

### 11.1 기본 방침

1차 프로토타입에서는 벽 차폐 없이 순수한 구면 음파를 구현한다. 이를 통해 다음을 먼저 판단한다.

- 벽 너머 정보가 실제 플레이에서 과도한가
- 현재 방에서 보이는 표면만으로 충분히 자연스러운가
- 거리 감쇠만으로 정보량을 통제할 수 있는가
- 추가 차폐가 게임플레이 가치에 비해 복잡한가

물리적 반사, 회절, 다중 경로는 현재 제작 범위에 포함하지 않는다.

### 11.2 지각 기반 차폐 트릭

추가 차폐가 필요하다고 판단될 경우 전파 경로를 변경하지 않고, 음원과 플레이어 사이의 가림 정도를 하나의 `obstruction` 값으로 계산한다.

```text
obstruction: 0 = 직접 노출, 1 = 강하게 차폐됨
```

단일 Raycast의 이진 판정은 문 가장자리나 얇은 기둥에서 갑작스러운 전환을 만들 수 있으므로 권장하지 않는다. 음원 중심과 주변점을 향한 여러 Raycast의 차단 비율을 사용한다.

```text
obstruction = blockedSampleCount / totalSampleCount
```

초기 샘플 후보:

- 음원 중심
- 위와 아래
- 왼쪽과 오른쪽

### 11.3 판정 시점

첫 구현에서는 차폐 상태를 음파별로 한 번 계산하고 수명 동안 고정하는 방식을 우선한다. 플레이어나 음원이 문 가장자리를 지날 때 진행 중인 음파 전체가 갑자기 선명해지거나 흐려지는 현상을 피하기 위함이다.

두 가지 후보 시점을 비교 테스트한다.

1. 음파 발생 순간
2. 음파가 플레이어 위치에 도착하는 순간

두 번째 방식은 플레이어가 실제로 음파를 인지할 시점의 공간 상태와 일치한다. 플레이어 자신이 만든 발걸음과 박수는 직접음으로 분류하여 차폐 판정을 생략할 수 있다.

### 11.4 시각적 결과

차폐도는 음파의 반지름이나 도착 시각을 바꾸지 않고 다음 표현에만 영향을 준다.

```text
brightness       = lerp(1.0, 0.25, obstruction)
edgeSoftness     = lerp(0.0, 0.8, obstruction)
thickness        = lerp(1.0, 2.0, obstruction)
detailVisibility = lerp(1.0, 0.2, obstruction)
traceDuration    = lerp(1.0, 0.5, obstruction)
```

수치는 예시이며 플레이테스트로 결정한다.

차폐된 음파를 단순히 어둡게만 만들면 작은 소리와 구분하기 어렵다. 다음 성질을 함께 사용한다.

- 넓고 흐릿한 경계
- 감소한 세부 패턴
- 탁하거나 채도가 낮은 색
- 짧고 불안정한 잔상
- 실제 오디오의 고역 감쇠

### 11.5 오디오 결과

동일한 `obstruction` 값을 실제 오디오에도 전달한다.

```text
volume         = lerp(normalVolume, occludedVolume, obstruction)
lowPassCutoff  = lerp(openCutoff, occludedCutoff, obstruction)
```

벽 너머 소리는 고음이 크게 줄고 저음 위주로 들리도록 한다. 시각적 흐림과 오디오 저역 통과가 같은 차폐 값을 공유하여 플레이어에게 일관된 규칙을 전달해야 한다.

### 11.6 적용 시점

차폐는 1차 구현 범위에서 제외한다. 이후 필요성이 확인되면 음파의 전파
반지름과 도착 시각은 유지한 채, `Source`와 음원/Listener 위치를 이용해
시각 및 오디오 지각값에만 차폐를 적용한다.

## 12. 주파수 성격 확장

정밀한 주파수 시뮬레이션이나 FFT 대신 음파 프로필에 소수의 추상 밴드를 둘 수 있다.

```text
Low
Mid
High
```

표면과 차폐는 밴드별로 다른 반응을 보인다.

- 벽 너머: High를 크게 줄임
- 금속: High 계열 시각 패턴을 강조
- 물: Low 또는 Mid 계열의 넓은 잔상을 강조
- 흡음재: High와 Mid가 빠르게 감소

동일한 밴드 값을 실제 오디오 필터, 표면 패턴, AI 감도에 사용할 수 있다. 이는 물리 음향 시뮬레이션이 아니라 음원의 성격을 여러 시스템에 일관되게 전달하기 위한 게임플레이 데이터다.

이 기능은 기본 구면 시각화와 차폐 테스트가 완료된 이후 도입 여부를 결정한다.

## 13. 추가 가능한 표현 요소

다음 요소들은 구면 전파 로직을 변경하지 않고 선택적으로 추가할 수 있다.

### 13.1 방향 가중치

전파와 도착 판정은 구형으로 유지하면서 표면 밝기 또는 AI 감지 강도에만 방향 가중치를 적용한다.

- 박수는 전방이 조금 더 선명함
- 발걸음은 바닥 방향이 강함
- 비명이나 폭발은 전 방향이 강함

완전한 원뿔 전파로 바꾸지 않고 약한 가중치만 사용한다.

### 13.2 시각적 중요도

환경음이 공간을 계속 밝혀 핵심 어둠을 훼손하지 않도록 음파별 시각화 수준을 정할 수 있다.

- `Full`: 표면 형상을 명확히 표시
- `Hint`: 방향과 큰 윤곽만 표시
- `AudioOnly`: 논리 감지와 오디오만 사용

### 13.3 표면 노멀 반응

음원을 향하는 표면을 약간 더 밝게 표현할 수 있다. 반대편 표면이 완전히 사라지지 않도록 최소 밝기를 보장하고, 물리적 정확성보다 판독성을 우선한다.

## 14. 렌더링 구현 방향

현재 프로젝트는 Unity 6.3과 URP 17.3을 사용한다.

### 14.1 1차 구현

- 음파 반응 전용 URP 표면 셰이더
- 활성 음파 데이터를 전역 셰이더 배열 또는 버퍼로 전달
- 표면별 데이터는 `MaterialPropertyBlock`으로 전달
- 최대 16개의 시각 음파 처리
- 월드 좌표 기반 구면 교차 띠와 잔상
- Bloom을 이용한 제한적 발광 보강

### 14.2 후속 품질 개선

- 물, 위험, 트리거 표면 패턴
- 파면 전면과 잔상 밝기 분리
- 거리 기반 경계 폭과 세부 정보 감쇠
- 월드 공간 왜곡
- 중첩 시 포화 제어
- 필요할 경우 화면 공간 윤곽 보강

### 14.3 후순위 또는 제외

- RenderTexture에 모든 흔적을 지속 누적하는 구조
- 파면용 SphereCollider 생성
- 음파 반사와 회절
- 실제 음향 경로 추적
- 다중 반사 또는 포털 경로 렌더링
- Render Graph 기반 전용 렌더 패스

전용 렌더 패스는 표면 셰이더만으로 핵심 표현이 불가능하다고 확인된 경우에만 검토한다.

## 15. 구현 단계

### 단계 1 — 순수 구면 음파

- 전역 고정 전파 속도
- 음파별 범위, 두께, 잔상, 시각 및 청각 강도
- 표면과 만나는 파면만 렌더링
- 일반 표면과 물 표면 색상 구분
- 다중 음파 처리
- Listener 도착 이벤트
- 발걸음 Emitter 연결

### 단계 2 — 판독성 개선

- 거리 기반 밝기 감쇠
- 거리에 따른 경계 폭 변화
- 표면별 패턴과 잔상
- 약한 월드 공간 노이즈
- 중첩 시 밝기 포화 제어

### 단계 3 — 지각 기반 차폐

- 외부 음원부터 적용
- 다중 Raycast 기반 차폐도
- 음파별 차폐 상태 고정
- 시각적 흐림과 오디오 Low-pass 연결
- 문, 코너, 얇은 기둥에서 전환 테스트

### 단계 4 — 게임플레이 확장

- Low/Mid/High 성격 도입 여부 결정
- 물과 흡음 영역의 발생 수정값
- AI별 청각 감도와 음원 반응
- 음파별 시각화 중요도
- 필요할 경우 공간 단위의 저비용 차폐 보정

각 단계는 이전 단계의 전파 로직을 교체하지 않고 프로필과 해석 계수를 추가하는 방식으로 확장한다.

## 16. 프로토타입 검증 장면

GDD의 대표 상황을 축소한 방 하나로 첫 검증을 진행한다.

필수 구성:

- 일반 바닥
- 물 영역
- 벽과 기둥
- 문 또는 열린 통로
- 음파 Listener 하나
- 플레이어 발걸음
- 임의 위치에서 발생시키는 능동 음파
- 돌 충돌을 대신할 원거리 테스트 음원

### 16.1 1차 성공 기준

- 빈 공간에는 음파 구체가 보이지 않는다.
- 바닥, 벽, 천장에 연속적인 구면 교차선이 보인다.
- 물이 색상과 잔상 성질로 즉시 구분된다.
- Listener가 거리에 맞는 지연 후 정확히 한 번 반응한다.
- 큰 음파가 더 많은 공간 정보와 더 큰 AI 노출을 함께 만든다.
- 연속된 발걸음이 화면을 과도하게 포화시키지 않는다.
- 8~16개 음파가 겹쳐도 목표 프레임을 유지한다.
- 벽 너머 정보가 실제 게임플레이에서 문제가 되는지 판단할 수 있다.

### 16.2 차폐 확장 성공 기준

- 직접음과 차폐음의 차이가 시각과 오디오 양쪽에서 일치한다.
- 차폐음이 단순한 작은 소리와 구분된다.
- 문 가장자리에서 선명도나 음색이 갑자기 깜빡이지 않는다.
- 흐릿한 음파가 대략적인 방향은 전달하지만 정확한 방 구조를 과도하게 노출하지 않는다.
- 플레이어가 차폐 규칙을 별도 설명 없이 반복 경험으로 학습할 수 있다.

## 17. 디버그 도구

핵심 시스템이 보이지 않는 논리와 셰이더에 걸쳐 있으므로 다음 디버그 기능을 함께 구현하는 것을 권장한다.

- Scene View에서 음원 위치와 현재 반지름 표시
- 음파 ID, 카테고리, 시작 시각, 현재 반지름 표시
- 논리 음파 수와 시각 슬롯 수 표시
- Listener 도착 이벤트와 감지 강도 로그
- 표면 프로필과 발생 표면 타입 표시
- 차폐 단계에서는 샘플 Ray와 `obstruction` 값 표시
- 셰이더의 파면 전면, 잔상, 표면 패턴을 각각 단독 표시하는 모드

디버그 표현은 개발 빌드 또는 전용 토글에서만 활성화한다.

## 18. 테스트 항목

### 논리 테스트

- 거리에 따른 도착 시각 계산
- 최대 범위 밖 Listener 미감지
- 하나의 음파가 같은 Listener에 중복 전달되지 않음
- 시각 슬롯 제거가 논리 감지에 영향을 주지 않음
- 시간 배율과 일시정지 처리
- 음파 프로필과 표면 발생 수정값 결합

### 시각 테스트

- 바닥, 벽, 천장, 경사면의 구면 교차
- 카메라 이동 시 월드 패턴 고정
- 작은 두께에서의 깜빡임과 앨리어싱
- 가까운 파면의 과노출
- 다중 음파 중첩과 Bloom 포화
- 움직이는 오브젝트의 표면 반응

### 통합 테스트

- 발걸음 위치와 시각 파면 중심 일치
- 실제 발소리와 음파 발생 시점 일치
- AI가 플레이어 대신 음원 발생 위치를 조사
- 물 위 발걸음의 시각, 오디오, AI 노출 변화 일치
- 외부 음원의 차폐 시각과 Low-pass 강도 일치

## 19. 현재 미정 사항

다음은 프로토타입과 플레이테스트 후 결정한다.

- 최종 전역 전파 속도
- 음파별 기본 범위와 잔상 시간
- 동시 시각 음파의 최종 한도
- 벽 너머 정보가 차폐 없이 허용 가능한 정도
- 차폐 판정을 발생 시점과 플레이어 도착 시점 중 언제 수행할지
- 플레이어가 던진 돌에 차폐 표현을 적용할지
- Low/Mid/High 성격을 실제 시스템에 도입할지
- 흡음 영역이 전파 범위를 논리적으로 줄일지, 표현과 감지만 약화할지
- 방향 가중치를 적용할 음원 종류
- 모바일 또는 저사양 그래픽 품질에서의 시각 음파 한도

## 20. 범위 보호 원칙

새로운 음파 기능을 제안할 때 다음을 확인한다.

1. 구면 전파와 도착 시각을 유지한 채 표현 또는 감지 계수로 구현할 수 있는가?
2. 플레이어가 소리를 정보와 위험으로 동시에 사용하게 만드는가?
3. 시각과 오디오가 같은 규칙을 전달하는가?
4. 색상 외에도 경계, 패턴, 움직임으로 구분 가능한가?
5. 플레이어가 알 수 없는 정보로 불공정하게 실패하지 않는가?
6. 2~3개월의 제작 범위 안에서 플레이테스트 가능한가?

복잡한 물리적 정확성이 핵심 플레이 경험을 명확히 개선하지 않는다면 추가하지 않는다.
